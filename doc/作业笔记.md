# 嵌入式 C 培训笔记（8.10 作业）

## 一、题目 1：环形队列实现

### 实现要点

- FIFO 缓冲，解耦「产生命令的中断」和「处理命令的主循环」。
- `head`=下一个读的位置，`tail`=下一个写的位置，`(tail+1) % PACKET_QUEUE_SIZE` 取模回绕。
- `count` 区分空/满：`==0` 空，`==PACKET_QUEUE_SIZE` 满。
- 元素是 `command_packet` 结构体，直接整体赋值：`q->buf[q->tail] = *pkt;`。
- push 先判满、pop 先判空。

### 关键代码位置

`common/src/command_pack_queue.c`：init / is_empty / is_full / push / pop。

## 二、题目 2：位运算封包（4 字节协议）

### 实现要点

- 协议包：`{0x0A, 0x5A, cmd, checksum}`。`cmd` 一个字节：**高 4 位 = 闪烁次数，低 4 位 = LED 掩码**。
- 拼命令字：`cmd = (blink_count << 4) | (led_mask & 0x0F)`。
- 校验和 = `header[0]+header[1]+cmd` 的低 8 位（3 个字节相加）。

### 关键代码位置

`command_pack_create`（command_pack_queue.c）

## 三、题目 3：位运算解包

### 实现要点

- 包头校验：`header[0]<<8 | header[1]` 与 `HEADER_WORD`（0x0A5A）比较。
- 校验和重算比对，防传输损坏。
- 解命令：`blink_count = cmd >> 4`（移位取高 4 位），`led_mask = cmd & 0x0F`（掩码取低 4 位）。
- 都过才写输出参数并返回 true；任一失败返回 false。
- **LED 掩码翻译**：协议层掩码 bit0~3（LED_MASK_LED1=0x01）≠ 硬件引脚 PB3~6（LED1_PIN=0x08），`command_led_execute` 内必须翻译，否则灯不亮。

### 关键代码位置

`command_pack_unpack`（command_pack_queue.c）+ main.c `USER CODE 3` 主循环。

## 四、题目 5：函数指针表状态机

### 实现要点

- 枚举定义状态；`typedef void (*state_func)(void);` 定义函数指针类型。
- 状态表：`static const state_func state_table[STATE_COUNT] = { [STATE_IDLE] = state_idle_run, ... }`，下标=状态枚举，值=函数指针（指定初始化）。
- 主循环只查表调函数：`state_table[current_state]()`，不写 switch。
- 状态切换在各运行函数内部改全局 `current_state`。
- 状态函数内的步进/翻转变量要加 `static` 记住上次值。

### 关键代码位置

`user/src/state_machine.{c,h}`，main.c 调用`state_machine_run()`。

## 五、知识点

- **结构体**：相关变量打包成一个类型；同类型结构体可 `=` 整体赋值。
- **指针**：`q->head` 即 `(*q).head`；`const` 指针 = 只读契约。
- **输出参数**：传地址，函数里 `*pkt = ...` 写回；漏写 `*` 是常见坑。
- **环形队列**：取模回绕避免搬数据；满时策略=丢弃返回 false。
- **位运算**：`<<` `>>` `&` `|` `~` `^`；位运算用无符号类型；判断某位要加括号 `(flags & BIT) != 0U`。
- **拼包 / 解包**：一个字节装两个字段（高 4 位 + 低 4 位），移位拼、移位 + 掩码拆，封包解包互为逆运算。
- **通信协议思想**：帧头（定位消息起始）+ 命令（内容）+ 校验和（防错）。
- **函数指针**：`(*f)(void)` 星号和名字必须一起加括号；函数名本身就是入口地址，赋值不带 `()`；函数指针数组 = 状态/命令表。
- **掩码翻译**：协议层的逻辑编号和硬件引脚可能是两套编码，在边界处要做映射翻译。

## 六、调试记录

### 拼写错误 → "隐式声明 + 未定义符号"

`packet_quene_is_full` 应为 `packet_queue_is_full`。`declared implicitly` + `Undefined symbol` 同时出现 = 函数名和定义对不上，先对照头文件逐字母核对，不要直接怀疑逻辑。

### 灯不亮：pop / unpack 的 3 个逻辑 bug

1. `pop` 赋值方向反了：应为 `*pkt = q->buf[q->head];`（输出参数是"往外写"）。
2. `pop` 返回 `false`，导致 main 的 `if(pop)` 整块跳过。
3. `unpack` 忘了写输出参数：需 `*cmd_high = ...; *cmd_low = ...;`。

**教训**：能编译 ≠ 逻辑正确。现象不对时从结果倒推链路逐级排查（执行→pop 返回值→unpack 校验→输出参数）。

## 八、作业要求改动

### 旧（5 字节）的问题

1. **字节浪费**：次数、掩码都只用 4 位有效数据，却各占一个 8 位字节。
2. **协议与硬件耦合**：协议字段直接用硬件引脚掩码 `LED1_PIN`（GPIO_PIN_3=0x08）。协议该描述"逻辑对象"（第 1 颗 LED），不该绑定"物理引脚"（PB3）；换板子挪引脚协议就得跟着改。
3. **字段约束不清晰**：`cmd_high` 8 位全当次数没体现真实约束（015 就够）。

### 修改思路

1. **压缩**：`cmd` 一个字节 = 高 4 位次数 + 低 4 位掩码，`cmd = (blink_count << 4) | (led_mask & 0x0F)`。
2. **解耦**：协议层用逻辑掩码 `LED_MASK_LED1~4`，硬件层用 `LED1_PIN`，在 `command_led_execute` 边界处做翻译。
3. **位段用宏管理**：`CMD_BLINK_SHIFT` / `CMD_LED_MASK`，要改只改一处。
4. **封解包互为逆运算**：拼用 `<<4` + 掩码，拆用 `>>4`、`& 0x0F`。
